# Pearls AQI Predictor

Forecasts Karachi's Air Quality Index (AQI) 24, 48 and 72 hours ahead. The whole system runs on free tiers: GitHub Actions collects data and retrains, MongoDB Atlas stores features and models, and Streamlit serves the dashboard.

🔗 **Live dashboard:** https://aqi-predictor-clgefbv7tu87ehnluaddsu.streamlit.app/
📄 **Technical report:** [`report/report.pdf`](report/report.pdf) · 📓 **EDA:** [`notebooks/eda.ipynb`](notebooks/eda.ipynb) · 🛠 **Run your own copy:** [`docs/setup.md`](docs/setup.md)

> [!IMPORTANT]
> **AI disclosure.** Much of this code was generated by AI coding assistants and later refined with AI. The author chose the design, directed the work, reviewed and tested the changes, and owns the result.
>
> **No guarantee.** The forecasts are experimental and can be wrong, especially during dust storms and smog events. Do not use them for health decisions; check official sources such as the Pakistan EPA or [aqicn.org](https://aqicn.org/city/karachi/) instead.

## How it works

```
AQICN API ──────┐
OpenWeather ────┼─→ Feature pipeline ─→ MongoDB Atlas ─→ Training pipeline ─→ Model registry ─→ Dashboard
Open-Meteo CAMS ┘      (hourly)          feature store       (daily)            (GridFS)
```

| What | When |
|---|---|
| Fetch AQI, weather and the CAMS air-quality forecast; compute features; check drift; store the 3-day forecast | Every hour |
| Backfill targets, run the imputation ablation, train every model, promote a champion | Daily, 02:00 UTC |
| Re-enable both workflows, so GitHub does not switch them off after 60 quiet days | Daily |
| Dashboard reads the stored forecast and leaderboard | On page load (cached) |

If the hourly pipeline fails, it emails the maintainer a link to the failed run.

## Models

Each model predicts the change from the current AQI (a residual). Every score is compared with *persistence*, the naive forecast that AQI in 24 hours will equal AQI now.

| Model | Kind | Can become champion |
|---|---|---|
| Ridge | Linear baseline | Yes |
| XGBoost, LightGBM, CatBoost | Gradient boosting, tuned with Optuna | Yes |
| Voting and Stacking ensembles | Combinations of the above | Yes |
| **Chronos-Bolt** (`amazon/chronos-bolt-tiny`) | Pretrained time-series model, used zero-shot: it sees only the AQI history and is never trained here | No |
| **CAMS** (via Open-Meteo) | The Copernicus atmospheric model's own PM2.5 forecast, converted to AQI | No |

Chronos-Bolt and CAMS are outside reference points. They show whether the trained models beat a general-purpose forecaster and a physics-based forecast. They cannot be promoted: Chronos would need torch in the hourly job, and CAMS is a forecast we read, not a model we own. The CAMS score uses only test hours that have a logged CAMS forecast, so it appears after the first few weeks of logging.

### Choosing the champion

A challenger must pass three gates: positive skill against persistence, no overfitting, and an Index of Agreement (IoA) of at least 0.15. Models that pass are ranked by TOPSIS over out-of-fold RMSE, IoA, skill score and MAE. A challenger replaces the champion only if it beats the champion's TOPSIS score by at least 1%, so near-ties do not cause churn.

RMSE alone rewards models that predict close to the mean. IoA (Willmott, 1981) measures how well a forecast follows the actual rises and falls, which is why it is both a gate and a ranking factor.

### Other design choices

- **Ground truth:** AQI computed from PM2.5 with the US EPA breakpoint formula.
- **Loss:** Huber loss for the boosters, so spike hours do not dominate training.
- **Multi-output:** the 24h, 48h and 72h forecasts are predicted together rather than chained, so errors do not compound.
- **Features:** about 50, including lags from 1 hour to 7 days, 24-hour rolling statistics, Fourier time terms, STL decomposition and physics-motivated terms such as a mixing-height proxy.
- **Scaling:** log(x+1) then RobustScaler for skewed pollutants, fitted on training data only.
- **Intervals:** conformal prediction gives the uncertainty band on the forecast chart.
- **Leak guard:** the `forecast_leads` feature group is switched off in code. The historical backfill filled it with observed future values, which equal the targets.

## Dashboard

1. **Live Forecast:** current AQI gauge, the 3-day forecast with its uncertainty band, and a banner when AQI is hazardous.
2. **Leaderboard:** every model from the latest run with its metrics, including Chronos-Bolt and CAMS.
3. **Ablation Study:** which feature groups help or hurt accuracy, updated by the training job.
4. **Feature Importance:** SHAP values for the current champion.

The footer shows how much of the 512 MB free database is in use.

The forecast is computed hourly and stored, so the dashboard never runs a model itself. Streamlit Community Cloud puts idle apps to sleep, so the first visit can take 10 to 20 seconds.

## Storage

MongoDB Atlas is both the feature store and the model registry; champion model files live in GridFS. Old data expires automatically so the database stays inside the free tier's 512 MB:

| Collection | Contents | Retention |
|---|---|---|
| `aqi_features` | One row per city and hour: features and 24/48/72h targets | Kept (training data) |
| `predictions` | Stored 3-day forecast | 7 days (TTL index) |
| `prediction_log` | Past forecasts, for the track-record chart | 90 days (TTL index) |
| `cams_forecasts` | CAMS forecasts logged each hour | 120 days (TTL index) |
| `model_metadata` | Current leaderboard, one document per model | Overwritten each run |
| `training_history` | Every model from every run, with metrics, commit SHA and feature groups | Last 90 runs |
| `oof_predictions` | Out-of-fold predictions for the champion | Overwritten |
| `ablation_results` | Feature-group ablation scores | Overwritten |
| `drift_log`, `drift_baseline` | PSI drift tracking | Last 720 rows |
| `feature_overrides` | Feature groups switched on or off by the ablation | One document |
